You are implementing ONE independent module of a traffic signal
simulation prototype called JCTRL (Junction Control).

Your module is the SCENARIO ENGINE.

IMPORTANT:
This module must be completely independent of rendering.

The architecture is:

Scenario Engine
        ↓
   VehicleState[]
        ↓
Intersection Blueprint

The Scenario Engine generates and updates the state of vehicles.
It does NOT render them.

YOUR RESPONSIBILITY:

Implement a minimal traffic scenario engine capable of generating
vehicles entering a four-way intersection and updating their state
over simulation time.

The engine must support at least these scenarios:

1. Balanced traffic
2. Heavy North/South traffic
3. Heavy East/West traffic
4. Rush-hour traffic

The MVP does NOT require realistic traffic physics.

Vehicles only need simple movement and waiting behavior.

VehicleState contract:

{
  "id": string,
  "x": float,
  "y": float,
  "speed": float,
  "direction": "N" | "S" | "E" | "W",
  "vehicle_type": "car" | "bus" | "truck" | "ambulance",
  "waiting": boolean
}

The Scenario Engine must produce:

VehicleState[]

at every simulation tick.

The engine should expose something similar to:

scenario_engine.tick(dt) -> VehicleState[]

The engine must NOT:
- render anything
- use Pygame
- calculate traffic signal decisions
- implement the ML model
- modify SignalState
- know anything about the UI

The engine should support a configurable/random seed so that the same
scenario can be reproduced for baseline vs JCTRL comparison.

IMPORTANT:

The intersection geometry can be represented using simple coordinates.
Assume a fixed 4-way intersection.

Vehicle movement should be deterministic and simple.

For the MVP:
- vehicles enter from one of N/S/E/W
- vehicles travel toward the intersection
- vehicles may stop when waiting
- vehicles may pass through when appropriate
- vehicles eventually leave the simulation

Do not build sophisticated physics.

TECHNOLOGY:

Use Python.

Use standard library where possible.

Do NOT depend on Pygame.

Keep this module independently executable.

Return:
1. Project structure
2. Complete source code
3. Public API
4. Example usage
5. A small standalone test/demo that prints generated VehicleState[]
6. Integration instructions for another developer who will consume
   VehicleState[]
